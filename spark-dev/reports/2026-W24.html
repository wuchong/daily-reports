Eliminating startup time in local dev/test loop

2 条回复 · 3 位参与者

Nicholas Chammas 提议通过让 `.remote("local")` 默认在后台启动持久化 Connect 服务器，以消除本地开发循环中 SparkSession 约 3 秒的启动延迟。Serge Rielau 对此表示支持，但 Holden Karau 担心默认启动后台进程会违背用户预期（如崩溃后重启 Python 期望服务器也重启）。讨论核心在于如何平衡开发效率提升与用户对后台进程管理的预期。

@Nicholas Chammas: 建议让 `.remote("local")` 默认在后台创建持久化 Connect 服务器，并增加 CLI 工具（如 spark connect start/stop）进行管理，将启动时间缩短至 1 秒内。

@Serge Rielau: 强烈支持该提议。

@Holden Karau: 对默认启动持久化服务器持保留意见，担心用户在驱动崩溃后重启 Python 时预期服务器也会被终止，建议需谨慎处理默认行为和用户提示。

目前处于提案征集反馈阶段，尚未达成最终共识，后续需重点解决后台进程生命周期管理与用户预期不一致的问题。
