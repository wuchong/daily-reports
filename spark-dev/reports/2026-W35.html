SPIP: FileType: native support for unstructured data in Spark

1 条回复 · 1 位参与者

该讨论提议在 SparkSQL 中引入新的数据类型 FILE（FileType），用于原生支持 PDF、图片、音视频等非结构化或大文件数据。该类型仅存储文件路径和少量元数据，使查询可在不读取文件内容的情况下进行过滤、连接和投影，从而提升性能并降低成本。提案人已关联 Parquet 新增的 FILE 逻辑类型，并准备推动投票。

@Burak Yavuz: 提议新增 SparkSQL 数据类型 FILE，用于以路径加元数据方式管理非结构化文件，避免直接写入二进制列或仅用字符串路径带来的问题。

@Burak Yavuz: 该设计可让引擎、文件格式和 UDF 统一理解文件类型，查询时仅在需要处加载文件字节，减少不必要的数据读取。

@Burak Yavuz: 提案已与 Parquet 新引入的 FILE 逻辑类型对齐，并计划在下周二发起投票。

目前尚未形成最终结论，但提案人计划于下周二启动投票，等待社区进一步反馈。

SPIP: Add the DECFLOAT data type

0 条回复 · 1 位参与者

本次讨论围绕 Spark 社区新增 DECFLOAT 数据类型的 SPIP 提案展开。提案人根据首次投票中的反馈修订了方案，放弃原 JNI/libbid 实现，改为采用自定义的 Java 原生 IEEE 754 兼容实现，并继续征求社区意见。

@Uroš Bojanić: DECFLOAT 用于支持 IEEE 754 decimal64/decimal128 十进制浮点数，弥补 DECIMAL 精度/标度限制与 DOUBLE 二进制舍入误差之间的空白。

@Uroš Bojanić: 根据首次 SPIP 投票反馈，提案已更新，放弃 JNI/libbid 方案，改用自定义 Java 原生 IEEE 754 兼容移植实现。

@Uroš Bojanić: 该类型将支持每值独立指数、十进制运算、带符号零、Inf 和 NaN，并通过配置开关在孵化期发布，保持现有 DECIMAL/DOUBLE 行为不变。

提案已根据反馈修订实现方案，讨论线程继续保持开放，等待社区进一步反馈和实质性意见。
