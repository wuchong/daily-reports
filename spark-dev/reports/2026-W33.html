@Allison Wang: 提议建立社区维护的 PySpark 数据源仓库，聚焦公共 Python Data Source API，不纳入 Spark core，并通过严格评审与淘汰机制保障可持续性。

@Nicholas Chammas: 提醒社区参考 Spark Packages 等历史项目失效的教训，建议分析其未能持续维护的原因，以避免新项目重蹈覆辙。

@Uroš Bojanić: 支持提案但指出应严格限定范围在 Python 数据源，并强调 AI 可降低开发成本，但长期维护、安全审查和测试仍需人工投入。

SPIP: Add the DECFLOAT data type

2 条回复 · 2 位参与者

讨论围绕在 Spark SQL 中新增 DECFLOAT 数据类型（IEEE 754 decimal64/decimal128）的 SPIP 提案展开，旨在填补 DECIMAL 与 DOUBLE 之间的空白。提案支持每值独立指数、十进制运算、Inf/NaN，并通过配置开关进行孵化，同时保持现有行为不变。讨论重点包括实现方式（JNI/libbid vs 纯 Java）以及类型提升时可能的隐式精度损失问题。

@Uroš Bojanić: 提出新增 DECFLOAT 类型，支持 IEEE 754 十进制浮点运算，弥补 DECIMAL 精度限制与 DOUBLE 二进制舍入误差之间的不足，并通过配置开关进行孵化。

@Shrirang Mhalgi: 质疑使用 JNI/libbid 实现是否经过权衡，担心引入原生依赖会带来平台构建复杂性和崩溃风险；同时指出 DECIMAL 到 DECFLOAT 的隐式类型提升可能导致精度丢失，建议在 ANSI 模式下要求显式 CAST。

@Uroš Bojanić: 已根据反馈更新 SPIP 文档，补充了 JNI 与 Java 实现的权衡分析，并收紧了类型提升规则以避免隐式精度损失。

提案获得积极反馈，主要设计问题已被纳入文档修订；下一步继续征求社区对方案范围与实现细节的意见。
