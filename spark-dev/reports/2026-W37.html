[SDP] withColumn over an in-graph table seems to lose its dependency edge on reruns

1 条回复 · 2 位参与者

Eric Smith 报告在 Spark Declarative Pipelines 中，物化视图使用 withColumn 读取已存在的 in-graph 表时，重跑会丢失依赖边，导致与上游表并行执行并读取被清空的数据，结果为空；而使用 select 的对照组正常。他推测原因是 SparkConnectPlanner.transformWithColumns 对 child 做了 eager analysis，表已存在时解析成功，导致 FlowAnalysis 只为 UnresolvedRelation 注册依赖。Andreas Neumann 确认这是真实 bug 且测试覆盖不足。

@Eric Smith: 疑似根因是 transformWithColumns 提前解析子计划，使已解析关系绕过 FlowAnalysis 中仅针对 UnresolvedRelation 的依赖注册。

@Andreas Neumann: 确认这是真实 bug，并建议提交 Jira 和 PR 修复。

SPIP: Add the DECFLOAT data type

1 条回复 · 2 位参与者

讨论围绕 Spark 新增 DECFLOAT 数据类型的 SPIP 展开，核心焦点是其逻辑值域是否应包含 IEEE 754 非有限值（+Inf、-Inf、NaN、有符号零）。发起者强调值域属于不可逆决策，而位数和算术实现可后续调整；Gengliang Wang 表示支持并认为应先确定值域，其他实现细节可后续评审。

@Uroš Bojanić: DECFLOAT 应支持 IEEE 754 非有限值，因为这是不可逆的值域决策；仅有限值类型无法表达无界/未定义业务状态，且会迫使应用用 NULL 混淆语义。

@Gengliang Wang: 支持定义包含有符号零、正负无穷和 quiet NaN 的 DECFLOAT，认为这些是数值而非 SQL NULL，有助于跨语言/引擎的数据保真和往返兼容。

初步形成共识：应优先确认 DECFLOAT 的 IEEE 非有限值值域，并支持推进 SPIP；类型强转规则、执行实现、外部 API 和 Parquet 编码等细节仍需后续评审。

@Tamir K: 建议在 Spark on Kubernetes 的通用 volume 配置中新增 ConfigMap 卷类型，支持通过 spark.kubernetes.driver/executor.volumes.configMap.* 属性挂载已有 ConfigMap。

@Tamir K: 当前通过 driver/executor pod template 处理挂载，在多租户场景下会导致模板合并复杂，且用户需要了解或维护平台级 pod 配置。

@Tamir K: 提到 2018 年类似提案 SPARK-25500 / PR #22536 曾因应使用 pod template 而被拒绝，因此询问维护者当前是否仍倾向该立场或愿意重新考虑。
