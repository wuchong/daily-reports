Add a git trailer to manually skip post merge CI for spark

7 条回复 · 5 位参与者

讨论旨在通过引入 Git trailer（如 'CI: skip'）手动跳过不必要的合并后 CI，以缓解 Spark 项目 CI 资源紧张的问题。参与者探讨了通过 PR label 辅助实现该功能的可行性，并讨论了如何利用节省下来的资源增加测试覆盖率。

@Tian Gao: 提议在 commit message 中增加 Git trailer（如 'CI: skip'）来手动跳过安全提交的合并后 CI，以节省资源并增加定时 CI 的运行频率。

@Wenchen Fan: 建议引入 PR label，由合并脚本自动将其转换为 commit message 中的 trailer，以降低提交者手动编辑信息的难度。

@Ruifeng Zheng: 指出 GitHub labels 曾因安全问题被禁用，并建议合并后 CI 无需针对每次提交运行，可改为每 N 次提交运行一次。

初步倾向于通过扩展合并脚本来自动添加跳过 CI 的标记，但具体实现方式需考虑 GitHub labels 的安全限制或寻找替代方案。
