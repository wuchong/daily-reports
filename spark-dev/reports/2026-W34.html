2 条回复 · 3 位参与者

@Shazeb Khan: 当前 Driver 主机名格式会因 Kubernetes 默认 ndots:5 和 search domains 产生两次失败 DNS 查询，建议将 spark.driver.host 改为仅使用 Service 名称以减少解析延迟。

@Uroš Bojanić: 支持修复该问题，倾向于使用带末尾点的完整 FQDN（可配置域名）作为更稳健方案，也可接受仅用 Service 名作为最小修复，并建议提交普通 K8s JIRA。

@Dongjoon Hyun: 建议先尝试现有配置 spark.kubernetes.executor.useDriverPodIP，该能力在 Spark 4.1 引入并将在 4.2 默认启用，可让 executor 直接使用 Driver Pod IP，规避 DNS 解析问题。

初步建议是提交 K8s 相关 JIRA 继续讨论修复方案；同时可优先评估或启用 spark.kubernetes.executor.useDriverPodIP 作为现有替代方案。

Subject: Do people disable S3 lifecycle expiry on Structured Streaming checkpoint dirs?

0 条回复 · 1 位参与者

Dibyendu Bhattacharya 提出在 Spark Structured Streaming 使用 S3 存储 checkpoint 时，因后台维护任务未能及时生成快照、而 S3 生命周期策略又过期删除旧 delta 文件，导致状态读取失败和 checkpoint 损坏的问题。他计划取消对 checkpoint 前缀的 S3 生命周期过期，并改用基于文件是否仍被引用的清理机制，同时询问社区是否有更安全的保留策略或按查询调整 shuffle 分区的实践经验。

@Dibyendu Bhattacharya: S3 生命周期过期可能删除仍被 checkpoint 引用的历史 delta 文件，导致重启时报 'Error reading delta file ... does not exist'，因此基于时间的过期策略存在正确性风险。

@Dibyendu Bhattacharya: 后台维护任务若因触发过快或资源不足而落后，系统会依赖从初始版本开始的完整 delta 链，增加被生命周期策略破坏的风险。

@Dibyendu Bhattacharya: 建议移除 checkpoint 前缀的 S3 expiry，并改为检查文件是否仍被引用的清理方式，同时考虑按查询调整 spark.sql.shuffle.partitions 作为缓解措施。

初步倾向是不再对 Structured Streaming checkpoint 目录使用基于时间的 S3 生命周期过期，而采用基于引用关系的清理策略；下一步是征询社区是否有安全的有界保留实践或针对多状态规模查询的参数调优方案。

@Shazeb Khan: Spark 会无条件用默认的 `https://kubernetes.default.svc` 覆盖 Fabric8 自动获取的集群内 IP 配置，从而引发额外 DNS 查询和 NXDOMAIN 响应。

@Shazeb Khan: 建议修改 SparkKubernetesClientFactory：只有在非集群内运行或用户显式指定了自定义 master URL 时才调用 `withMasterUrl`。

@Shazeb Khan: 该修复可保留外部提交或跨集群场景下用户提供的 master 配置，同时消除默认集群内场景的不必要 DNS 解析。

邮件内容未包含社区反馈或最终结论，当前进展为问题提出与修复方案征集意见阶段；下一步是等待社区确认该方案是否为正确修复方向。
