@Peter Toth: 否认抄袭，解释称是在处理其他 PR 时独立发现并修复了该 Bug，因疏忽未检查现有工单；并指出 Asif 引用的过往案例中，最终合并的方案与 Asif 的不同。

Native memory cooperation: let BlockManager manage external-engine payloads

0 条回复 · 1 位参与者

讨论旨在解决原生执行引擎内存无法作为一等公民参与 Spark 存储内存核算的长期痛点。Chang Chen 提出了让 BlockManager 管理外部引擎负载的机制，但 Kent Yao 指出该方案无法实现宣称的“统一 LRU”，因为原生块无法更新访问顺序，导致其被不公正地优先驱逐。

@Chang Chen: 指出原生引擎内存无法参与 Spark 存储内存核算的问题，并提出了让 BlockManager 管理外部引擎负载的具体机制。

@Kent Yao: 反驳了提案关于“统一 LRU”的属性，指出由于原生块无法在读取时更新其在 LinkedHashMap 中的位置，会导致其被优先驱逐，而非真正的 LRU。

@Kent Yao: 提出解决方案需明确取舍：要么引入 touch API 并承担同步查找的性能开销，要么重新定义并接受原生块的实际驱逐策略。

目前尚无定论，下一步需要提案作者回应 Kent 提出的技术质疑，即决定是否引入 touch API 及其开销，或修正关于驱逐策略的描述。
