Blockers for Apache Spark 4.3.0 RC

5 条回复 · 4 位参与者

Apache Spark 4.3.0 的 RC1 发布失败，发布经理 Jungtaek Lim 向社区征集阻塞问题（blocker）的状态和解决时间，以便决定何时切出 RC2。多位开发者反馈了需要合并的修复，包括 API 不一致、事件日志回归问题以及个别 backport 问题。后续大部分阻塞项已解决或等待 CI 合并，但发现新的影响 4.2.0+ 的阻塞问题，需修复后再触发新的 RC。

@Jungtaek Lim: 作为发布经理，要求 blocker 负责人提供阻塞原因和预计解决时间，以避免盲目发布 RC2 再次失败；后续确认多数 blocker 已处理，但发现新的 SPARK-59919 阻塞项。

@Gengliang Wang: 请求等待 SPARK-59841 / PR #59119 合并，以修复 loadTable 与 loadChangelog API 的不一致问题，并希望再给 1–2 天 review 和合并时间。

@L. C. Hsieh: 指出 branch-4.3 包含 SPARK-59407 引入的两个回归：事件日志字节限制被按 UTF-16 字符数两倍检查，以及 ReplayListenerBus 的公共无参 JVM 构造函数被移除，建议合并 PR #59074 后再切 RC。

社区同意等待相关修复合并后再推进发布；当前主要 blocker 大多已解决或等待 CI，但需先修复新发现的 SPARK-59919，随后由发布经理触发下一个 RC。

Automated AI code review on new Spark PRs (trial)

5 条回复 · 5 位参与者

Hyukjin Kwon 在 Spark 社区发起基于 Claude 的自动化 AI 代码评审试验，对新 PR 进行多轮检查并以普通评论形式发布带严重级别的意见，不批准、不阻塞合并。社区整体支持试验，但强调 AI 评审只能作为辅助手段，不能替代 committer 的人工评审，并建议增加控制机制以减少噪音和风险。

@Hyukjin Kwon: AI 评审仅发布评论，不进行批准或要求修改，也不影响 PR 合并；计划试运行一周后迁移到独立账号。

@Jungtaek Lim: 需明确 AI 评审只是辅助流程，最终内容和责任仍由发布者和 committer 承担，不能替代主要人工评审。

@Dongjoon Hyun: 建议为评审机器人增加保护措施，如通过 GitHub label 禁用评审、限制 ASF Jira API 调用，避免过度请求或被封禁。

初步共识是支持继续试验，但需明确其辅助定位，并考虑增加可选退出机制和防护措施；Hyukjin 计划一周测试后分享更多细节。

Release Apache Spark 4.0.5

2 条回复 · 2 位参与者

本次讨论围绕 Apache Spark 4.0.5 维护版本的发布提议展开。Uroš Bojanić 提议将 4.0.5 作为与 4.2.1 和 4.1.4 协调的伴随维护版本发布，并指出自 4.0.4 以来已积累 56 个 JIRA 和 72 次提交，用于修复正确性和稳定性问题。他还提到 4.0.x 将在 2026 年 11 月结束 18 个月的支持周期，因此 4.0.5 可能是倒数第二个面向 4.0 用户的版本。

@Uroš Bojanić: 提议发布 Apache Spark 4.0.5 作为维护版本，计划在 4.1.4 RC2 之后立即发布 4.0.5 RC1。

@Uroš Bojanić: 指出 branch-4.0 自 4.0.4 以来已有大量修复提交，且 4.0.x 即将结束支持周期，因此该版本对 4.0 用户较为重要。

@Jill Klask: 对讨论内容提出质疑，认为这些工作没有实际意义，并提到与 Walmart Spark 相关的问题。

Uroš Bojanić 已决定推进 4.0.5 RC1 的发布，并计划在 4.1.4 RC2 之后进行。

初步方向是支持该特性并以新 JIRA/PR 推进；下一步是请 Uroš 审核 PR #58634，并继续确认流程及 Python/Pandas UDAF 支持范围。
