Deprecate Equality Deletes in Iceberg V4

8 条回复 · 6 位参与者

讨论重启了在 Iceberg V4 中弃用 Equality Deletes 的提议，指出其读取成本高且阻碍 CDC 和索引等特性，建议转向 Deletion Vectors (DV)。参与者主要讨论了“仅标记弃用”与“直接禁止写入”两种策略，权衡了流式写入场景的替代方案成熟度。最终提议者转变立场，建议在 V4 规范中明确禁止写入 Equality Deletes，以推动引擎端改进。

@huaxin gao: Equality Deletes 读取昂贵且阻碍增量维护特性，提议在 V4 中禁止写入，依赖 DV 和持久化索引方案，流式任务可暂时停留在 V3。

@Maximilian Michels: 支持弃用，认为“仅标记弃用”过渡太软，倾向于在 V4 中直接禁止写入，以倒逼引擎尽快迁移。

@Manu Zhang / Xiening Dai: 担忧缺乏引擎无关的替代方案，若禁止写入会增加用户迁移成本或导致 V4 采用困难。

提议者最终决定采纳“在 V4 表中禁止写入 Equality Deletes”的方案，同时允许 V2/V3 表继续读取，并建议后续补充性能基准测试数据。

Breaking Change / Fixed Behavior in AvroSchemaUtil - LocalTimestamp -> Timestamp

@Russell Spitzer: 认为旧版行为属于 Bug，只要不破坏内部代码，直接修复是可接受的；Iceberg 项目不应承担通过参数保留旧有错误行为的责任。

初步结论是同意继续执行“修复优先”的策略，即接受破坏性变更以修正错误行为，不特意保留旧版逻辑。

Add Alibaba Cloud auth type for REST catalog

0 条回复 · 1 位参与者

杨国梁提议为 REST Catalog 增加阿里云内置认证支持，旨在解决用户目前需手动打包自定义 Jar 包的运维摩擦问题。该方案采用纯增量设计，引入双层抽象结构以兼容阿里云不同产品的签名差异，首期将实现支持 MaxCompute (ODPS) 的签名逻辑。

@杨国梁(国良): 现有的自定义 Jar 包方式存在分发和版本对齐的摩擦，内置 aliyun 认证类型可像 AWS sigv4 一样消除这一痛点。

@杨国梁(国梁): 设计上通过 AliyunAuthManager 和可插拔的 AliyunRequestSigner 接口，在保持认证类型名称稳定的同时支持未来扩展（如 OSS）。

@杨国梁(国梁): 实现范围包括在 core 中注册认证类型，并在 iceberg-aliyun 模块中添加通用认证层和具体的 ODPS 签名实现。

该提案为纯增量变更，不涉及规范修改或 API 破坏，目前处于向社区征集意见阶段，尚未明确下一步合并计划。
