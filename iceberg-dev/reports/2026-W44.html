Spark: use the catalog's Hadoop configuration when listing orphan files (#17862)

4 条回复 · 3 位参与者

讨论围绕 Spark remove_orphan_files 列举孤儿文件时仅使用 Spark session Hadoop 配置，导致与 table.io() 凭证不一致并在跨账号存储场景下访问失败的问题。Sebastian 提议通过 catalog 名称引入 spark.sql.catalog..hadoop.* 覆盖配置；Daniel 和 Russell 建议优先从 FileIO 获取配置以避免扩展 API。Sebastian 随后说明 S3FileIO 等非 HadoopConfigurable 场景无法从 FileIO 取得 Hadoop 配置，因此仍需走 catalog 配置路径。

@Sebastian Daberdaku: DeleteOrphanFilesSparkAction 列举文件时未使用 catalog 凭证，导致 AccessDenied 或看不到文件；建议新增 catalogName 方法，让列举使用 session Hadoop 配置加 catalog 的 hadoop.* 覆盖配置。

@Daniel Weeks: 建议检查 FileIO 是否实现 HadoopConfigurable，直接获取该表 IO 使用的精确配置，而不是通过 catalog 路径解决。

@Russell Spitzer: 支持优先尝试不扩展公共 API 的方案，认为当前行为与新增 API 之间的关联不够直接。

尚未形成最终结论；Sebastian 已说明从 FileIO 获取配置在 S3FileIO 等场景不可行。下一步需继续确认是否接受新增 catalogName API，若方向确定，再将改动移植到 Spark 4.2 及相关版本。

Kafka Connect CDC writes without equality deletes

1 条回复 · 2 位参与者

讨论聚焦于为 Kafka Connect Iceberg sink 引入不依赖 equality delete 的 CDC 写入方案，以恢复此前因性能顾虑暂缓的 delta writer/CDC 支持。提案将 CDC 设为可选项并保留默认 append-only，同时说明 append+MERGE 仍适合需要保留 row ID 或转换跟不上提交间隔的场景。当前进展集中在方案合理性、性能验证和并发写入影响。

@koodin 9: 该提案旨在让表始终不产生 equality delete，从而回应历史 issue、社区对 equality delete 的顾虑以及用户对 CDC/upsert 的持续需求；CDC 为可选功能，默认仍为 append-only。

@koodin 9: append+MERGE 仍更适合需要跨更新保留 row ID 的表，以及转换速度跟不上提交间隔的表；Kafka 基于主键的分区机制可缓解 CDC 写入的重分区问题。

@Péter Váry: 在合入前必须进行 equality delete 解析/相关转换的性能测试，并评估 compaction 与并发写入可能带来的提交饥饿问题；基础快照应使用当前表快照。

尚未形成最终结论；下一步是先进行性能测试和并发写入/压缩场景评估，再推进代码提交或方案落地。

Pluggable Puffin blob types and a compaction-aware lifecycle for data-file-scoped indexes

1 条回复 · 1 位参与者

@Alex Cruise: 建议为 Puffin blob 类型建立轻量但有约束的元数据机制，用于管理配置、作用域以及索引在删除和 compaction 中的交互方式。

@Alex Cruise: 提出“渐进式索引”背景，强调大型旧文件不适合重写，需要支持在文件写入后按需补充索引，以优化读密集查询。

@Alex Cruise: 该提案与 v4 二级索引提案互补，更关注过滤器或“负索引”场景，过期索引只会降低查询效率，不应影响查询正确性。
