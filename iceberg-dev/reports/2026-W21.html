Spec ambiguity: Avro schema for `day` partition transform fields in manifests

12 条回复 · 6 位参与者

讨论主要围绕 Iceberg 规范中 `day` 分区转换结果类型的定义模糊问题：规范定义为 `int`，但主流实现（Java、Python、Rust）实际写入的是 Avro logical `date` 类型。经过讨论，社区达成共识，决定修改规范以匹配主流实现的 `date` 类型，并利用 Avro 规范特性确保读取端的兼容性。

@Kevin Liu: 指出规范与实现存在不一致，Java/Python/Rust 写入 `date` 而 Go 写入 `int`，建议规范应与主流实现保持一致。

@Andrei Tserakhau: 提议写入端应输出 `date` 类型，读取端必须兼容两种格式，并提交 PR 以澄清规范文本，区分逻辑类型与 Avro 编码。

@Ryan Blue: 指出 Avro 规范要求读取端忽略不支持的逻辑类型注解，因此读取端兼容 `int` 和 `date` 是 Avro 原生支持的特性。

初步结论是将规范中 `day` 转换的结果类型改为 `date` 以匹配主流实现，同时添加历史背景说明；下一步行动是推进 PR #16446 的合并，并更新 Go 实现以对齐该行为。

Adding unregister table endpoint to REST spec

10 条回复 · 10 位参与者

Ryan Blue 提议在 REST 规范中新增 `unregister` 端点，旨在解决现有 `drop` 操作无法安全处理并发写入且可能误删文件的问题，以支持跨 Catalog 的表迁移。讨论中社区成员普遍支持该提议，并明确了其与 `dropTable` 在数据保留行为上的关键区别。

@Ryan Blue: 现有 `drop` 端点在并发操作下不安全，且多数 REST Catalog 会自动清理文件，新端点需返回元数据位置以确保状态一致性。

@Ajantha Bhat: 支持该提议，认为返回元数据位置能保证迁移的原子性，并建议补充 `unregister-view` 端点以保持功能完整性。

@Daniel Weeks: 澄清了 `purgeRequested=false` 仅允许延迟清理而不保证保留数据，`unregister` 则明确用于解除目录对数据的管理。

社区对该提案反响积极，Ryan Blue 计划若无重大异议将于本周启动投票流程。

Column Update File Representation

8 条回复 · 6 位参与者

讨论核心在于当存在删除向量（DVs）时，列更新文件应如何表示行：是采用“位置对齐”（选项1，填充NULL）还是“应用删除”（选项2，仅存存活行）。目前讨论倾向于选项1，因为它能实现零拷贝拼接且跨引擎兼容性更好，但需要解决统计信息偏差和存储开销问题。

@Gang Wu: 支持选项1，认为其更符合未来的列族功能设计，允许基于隐式行对齐的零拷贝拼接。

@Gábor Kaszab: 测量显示存储开销不是决定性因素，建议无论选哪种都保留 `_pos` 列以便调试，且 NULL 填充带来的开销可接受。

@Andrei Tserakhau: 分享 Delta 社区经验，他们选择了选项1以避免复杂的向量化对齐，并强调需在规范中明确统计信息（如 null_count）的修正规则。

初步结论倾向于采用选项1（位置对齐），下一步需在规范中明确统计信息的修正方式，并解决 Rust 实现中的行组对齐问题。
