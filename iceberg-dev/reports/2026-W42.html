Extend Thur's biweekly sync to both File and Vector types (starting Oct 8)

3 条回复 · 3 位参与者

社区讨论 Iceberg 双周同步扩展到 File 与 Vector 类型，重点推进 Vector 类型规范，初步方向是定义固定长度、非空的 1D 数值向量，并先基于 Parquet 支持 int、long、float、double。对于 int8 和 float16，Peter 提出作为基础原始类型加入以支持 AI 向量索引，但社区担心其通用性并建议先限制为向量元素类型。

@Yan Yan: 会议总结建议初始向量规范保持简单：支持固定长度、非空、有限数值的一维向量，先支持 int、long、float、double，距离函数和稀疏向量暂不纳入。

@Péter Váry: 主张为 AI 向量索引支持 int8 和 float16，并提交 draft PR；认为二者是清晰标量类型，应作为 Iceberg 常规原始类型而非仅限向量元素。

@Philipp Fischbeck: 质疑将 int8、float16 扩展为通用原始类型的必要性，建议先仅允许作为向量元素类型，避免影响 bounds、schema evolution 等规范。

初步结论是先推进简单向量类型规范并由 Yan Yan 更新 spec PR；int8、float16 等窄类型是否成为通用原始类型尚未达成一致，建议另开 DISCUSS 线程讨论。

make appendUpdate in BaseTransaction public

0 条回复 · 1 位参与者

讨论是否将 BaseTransaction 中的 appendUpdate 方法公开，以便在事务中支持自定义更新（如写入专有索引的 Puffin 统计文件）并处理冲突重试。提议方认为现有 SnapshotAncestryValidator 只能覆盖校验，无法封装统计文件重写的重试逻辑；appendUpdate 引入者则建议先评估现有公开验证机制是否足够。

@Filip (dzeri96): 每次 append 都需要更新专有索引的 Puffin 统计文件，若事务冲突需要重读最新状态并重写文件；公开 appendUpdate 可通过自定义 PendingUpdate 将重试范围限制在统计文件，而不影响数据文件。

@Hongyue Zhang: 作为引入 appendUpdate 的 PR 作者，提出可以先确认冲突检测与解决语义是否能用 1.11 中公开的 SnapshotAncestryValidator 表达，因为它会在元数据刷新和提交重试时执行。

@Filip (dzeri96): 认为这更多是哲学问题：公开扩展点有助于基于 Iceberg 构建自定义能力，但也可能带来数据格式或兼容性问题，长期希望部分能力能逐步上游化。

目前尚未形成最终结论。下一步是继续讨论 SnapshotAncestryValidator 是否能满足该用例，以及公开 appendUpdate 是否会带来兼容性风险，并建议在原邮件线程或相关 PR 中深入补充需求细节。
