Write-path gap for field-id-bound policy during schema evolution

4 条回复 · 4 位参与者

讨论主要围绕模式演进期间字段 ID 绑定策略的“写入路径缺口”问题，即新列在提交后到策略绑定前存在未受保护的时间窗口。议题进一步延伸至 REST 规范是否应标准化深入目录领域的写入端 API，社区正在评估是制定统一框架还是将其留作目录实现细节。

@Andrei Tserakhau: 指出这是规范尚未覆盖的元模式问题，倾向于通过“能力协商”而非强制标准化来解决目录领域的写入端 API。

@Sung Yun: 强调当前流程存在安全风险（Drift 和 Creation 问题），询问社区是否接受此限制或支持在同一事务中实现列创建与策略绑定。

@Prashant Singh & Yufei Gu: 认为这主要是目录实现层面的关注点，规范无需强制要求，现有设计已将此留作目录的选择。

初步倾向于将其视为目录能力或实现选择而非规范强制要求；Sung 将在即将召开的 Catalog 社区同步会议上进一步讨论该问题及更广泛的元模式议题。

Global Snapshot Consistency for Iceberg Tables

3 条回复 · 3 位参与者

讨论主要围绕如何为涉及多个 Iceberg 表的查询实现全局快照一致性。Xiening Dai 提议引入 LoadTables API 和 CSN 机制以解决当前规范缺乏跨表一致性的问题，讨论深入探讨了目录作为事实来源的可行性、联邦环境下的局限性以及对事务存储后端的要求。

@Xiening Dai: 提议 LoadTables API 以实现跨多表原子化读取元数据；认为目录已是事实来源，建议将事务边界限制在命名空间内。

@Andrei Tserakhau: 强调一致性依赖于目录作为唯一事实来源；指出在联邦/分片目录架构下单一读取操作无法保证一致性；指出该功能依赖目录具备原子多表操作能力。

@Maninder Parmar: 指出 CSN 提案与 LoadTables 思路一致，且 CSN 仅存于 TableMetadata 中，无需重写存储层工件。

议题已被接纳加入社区同步会议，将在会议中进一步讨论技术细节和边界定义。
