Spark: use the catalog's Hadoop configuration when listing orphan files (#17862)

9 条回复 · 4 位参与者

讨论围绕 Spark 删除孤儿文件时如何获取正确的 Hadoop/云存储凭证，尤其是 Glue 跨账号与 S3FileIO 场景。社区倾向于不为列表操作新增 catalogName 或 hadoopConf API，而是优先使用表 FileIO 自身配置，并将 PR 改为仅在 FileIO 支持 HadoopConfigurable 时使用其配置。S3FileIO 的根本修复将依赖后续基于 FileIO 的可扩展前缀/并行列表能力。

@Sebastian Daberdaku: 说明 Glue 跨账号下 remove_orphan_files 会因使用 session Hadoop 配置而 AccessDenied，并建议最终改为当 table.io() 支持 HadoopConfigurable 时使用其配置，不新增 API。

@Russell Spitzer: 认为 S3FileIO 等非 Hadoop FileIO 不应接受 Hadoop configuration，若用户假设 Hadoop 配置适用于 S3FileIO，是配置路径本身不正确。

@Jean-Baptiste Onofré: 不赞成把 Hadoop 列表作为第二 IO 路径，短期可让 HadoopConfigurable FileIO 使用自身配置，长期应通过 table FileIO 的并行/前缀列表解决凭证一致性问题。

初步结论是将 #17862 改为无新增 API 的小修复：当 table.io() 为 HadoopConfigurable 时使用其 Hadoop 配置，否则回退 session 配置；S3FileIO 场景暂用 prefix_listing，后续推进 #17790/#11906 的并行 FileIO listing 作为根本方案。

REST catalog spec: semantics of the metrics reporting endpoint when the server fails to process a report

4 条回复 · 4 位参与者

讨论聚焦 Iceberg REST catalog 的 metrics 上报端点在服务器处理失败时的语义，起因是 Polaris 考虑将指标持久化失败从返回 500 改为记录并返回 204。社区普遍认为指标上报与读写/提交路径解耦，失败不应导致主流程失败，但对是否需要在规范中明确 best-effort 以及失败时能否返回 204 进行了讨论。

@Anand Kumar Sankaran: Polaris 当前在指标写入失败时返回 500，拟改为记录失败、丢弃指标并返回 204，希望社区先明确 metrics 端点语义。

@Eduard Tudenhöfner: 指标上报是 best-effort，客户端不应重试；服务端可自行决定返回错误或记录后丢弃，规范无需进一步规定。

@Daniel Weeks: 规范无需明确写 best-effort，但服务端返回码应真实反映处理结果；客户端是否重试或忽略失败属于客户端实现问题。

初步结论是 metrics 上报独立于 commit，失败不应影响读写；规范暂不修改，但服务端不宜把实际失败伪装为成功码，是否重试由客户端决定。Anand 将把该讨论结果带回 Polaris 邮件列表继续决策。

Migrating Iceberg to Jackson 3

3 条回复 · 2 位参与者

社区讨论 Iceberg 从 Jackson 2 迁移到 Jackson 3 的过渡方案，重点是如何避免破坏公共 API 和 REST 生态。讨论逐渐收敛为先引入 Iceberg 自有的 JSON 绑定 shim、短期同时支持 Jackson 2 和 Jackson 3，再通过适配模块处理 REST 层依赖。

@Alex Dutra: 提出过渡期同时提供 Jackson 2 和 Jackson 3，并通过兼容性测试、移除 Json serde 与 REST 层中的 Jackson 2 类型来逐步完成迁移。

@Steve Loughran: 建议将 Jackson 绑定隐藏在 Iceberg 内部 API 后，弃用并逐步移除 Jackson 2，必要时可放入 legacy 模块，但要避免二进制不兼容影响用户升级。

@Jean-Baptiste Onofré: 支持先做 shim 重构并弃用 Jackson 类型 API，再通过测试开关或参数化测试验证 Jackson 2/3 行为；REST 层应通过独立适配模块提供 Jackson 2/3 module。

初步共识是先进行纯重构：引入 Iceberg 自有 shim 并弃用 Jackson 类型 API，再引入 Jackson 3 并短期共存；REST 层采用 adapter artifact 分离依赖。下一步建议先提交一个 PR，增加 shim 类型并迁移一个 parser 包作为参考，以便统一设计并并行推进后续改动。
