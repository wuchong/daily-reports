Extend Thur's biweekly sync to both File and Vector types (starting Oct 8)

5 条回复 · 3 位参与者

社区围绕为 AI 向量场景引入 int8、float16 等窄类型展开讨论，核心争议是这些类型应作为 Iceberg 常规原始类型，还是仅作为 Vector 元素类型。Péter 提供了 Parquet 存储 FLOAT/FLOAT16 embedding 的基准测试，显示 float16 在体积和读取性能上有优势，并排除了 ALP 编码方案。多数人认为新增窄类型需要单独深入讨论，Vector 类型本身可以先推进。

@Péter Váry: int8 和 float16 是 AI 向量场景必需，建议作为常规原始类型而非仅限 Vector；基准测试显示 FLOAT16 相比 FLOAT 可更小更快，ALP 不适合。

@Daniel Weeks: 添加更窄数据类型影响较广，应避免埋在 sync 后续邮件中，建议开启独立 DISCUSS 线程进行更广泛讨论。

@Russell Spitzer: Vector 类型可先独立落地，不必等待更多子类型；应先投票当前 Vector 类型，再单独讨论扩展哪些子类型及引擎支持能力。

初步方向是先推进 Vector 类型落地，并将 int8/float16/bf16 等窄类型的适用范围、格式映射和引擎支持放到后续 Vector sync 或独立 DISCUSS 线程中讨论；同时基准测试支持进一步评估 FLOAT16，写入优化需考虑关闭向量列统计并依赖表或 Schema 级信息。

@Kevin Liu: V4 manifest 已定为 Parquet，提议在 V4 中移除 ORC 和 Avro 作为数据文件格式，理由包括功能缺口、非 Java 实现支持不足和上游演进有限。

@Manu Zhang: 数据文件格式变更应另开线程讨论；倾向 Java 参考实现收敛到单一格式，但规范中保留多种格式选项。

@Péter Váry: 对元数据格式收敛不强烈，但希望数据文件层保持开放，以保留未来调整灵活性并验证 API 通用性。

初步结论是数据文件格式变更不在本线程继续展开，将由 Kevin 另开新线程讨论；社区倾向至少在数据文件层面保持格式开放，暂未形成移除 ORC/Avro 的最终决定。

Handling of non-key column stats for equality delete files (PR #18338)

1 条回复 · 2 位参与者

社区围绕 PR #18338 讨论 equality delete 文件中非键列统计信息导致的静默正确性问题：这些统计可能被误用于 metrics pruning，从而漏删查询结果。讨论焦点是是否还应读取并使用 equality delete 文件中非 equality ID 列的统计，以及应在读取 manifest 时丢弃这些统计，还是仅在过滤评估时忽略它们。目前倾向于忽略或清理这些非键列统计，但仍需更广泛的社区共识。

@Marius Grama: 指出 equality delete 文件中非键列可能包含 null 或哨兵值，但 ManifestReader 会把这些统计视为可靠并用于指标裁剪，可能导致应删除的行仍出现在查询结果中，因此提请社区讨论处理方案。

@Péter Váry: 说明 Flink 在非 upsert 模式下确实会收集非键列统计；鉴于 equality delete 正被逐步淘汰且 v4 已禁用，实际修复应忽略这些统计，并更倾向于在读取 manifest 时直接丢弃非键列统计。

尚未形成最终结论，但初步倾向是在读取 manifest 时丢弃 equality delete 文件的非键列统计；下一步是继续征求社区意见并确定 PR 的最终实现方式。

NaN and Infinity in JSON single-value serialization

1 条回复 · 2 位参与者

讨论 Iceberg 规范中 float/double 的 NaN、Infinity、-Infinity 等非有限值在 JSON 单值序列化中的缺失问题，以及各客户端实现不一致带来的兼容性风险。发起人建议在规范中明确序列化方式，并考虑沿用 Java 已写入的字符串形式。讨论初步倾向于标准化这些字符串并修复读取，而不是禁止写入。

@Andrei Tserakhau: 规范允许非有限浮点值，但 JSON 单值序列化要求 JSON number，导致无法合法写入；各客户端分别写字符串、null 或拒绝写，需要统一规范。

@Raghvendra Yadav: 支持标准化 Java 已使用的 NaN、Infinity、-Infinity 字符串，因为已有元数据存在；禁止写入会使历史数据不可读，且静默写 null 的风险更大。

初步倾向将非有限浮点值标准化为区分大小写的字符串并补充规范或一致性测试；下一步是更新规范、OpenAPI 类型和 iceberg-verification fixtures，并修复 Java 读取。
