Bug Report - ProducerBatch.split() Straddling Signed Int Max

0 条回复 · 1 位参与者

Chris Jakins 报告了 Kafka Producer 中的一个潜在 Bug：当 broker 因 MESSAGE_TOO_LARGE 拒绝批次并触发 ProducerBatch.split() 时，若序列号跨越 2^31，会产生负数序列号，导致 producer 停滞并最终抛出 BufferExhaustedException。他建议改用已有的 wrap-safe 辅助方法，并表示愿意提交 JIRA 和 PR。

@Chris Jakins: ProducerBatch.split() 在重新分配序列号时使用原始 int 加法，跨越 2^31 会产生负序列号，导致 producer 停滞和 BufferExhaustedException。

@Chris Jakins: 建议使用 KAFKA-7693 中引入的 wrap-safe 辅助方法替代原始 int 加法，修复只需一行代码。

@Chris Jakins: 表示愿意提交 JIRA ticket 并参与 PR 修复。

目前尚无社区回复或正式结论，提议的下一步是提交 JIRA ticket 并开展一行代码修复的 PR。
