KIP-1368: Client framework name and version

15 条回复 · 5 位参与者

讨论围绕 KIP-1368（客户端框架名称和版本）展开，重点包括如何在客户端配置和 API 中暴露框架信息、是否提升 ApiVersions 请求版本、字段长度约束，以及 Connect、指标和框架实例识别等扩展问题。经过多轮修改后，Jun Rao 已对更新后的 KIP 表示 LGTM，后续讨论转向部分边界场景和后续 KIP 的衔接。

@Jun Rao: 建议通过 ClientTelemetryContext 公共 API 暴露客户端资源标签，避免插件实现依赖内部类转换；同时关注 ApiVersions 版本升级策略和字段长度约束。

@Andrew Schofield: 已按要求更新 KIP，包括添加 ClientTelemetryContext 方法、明确 ApiVersions 将随 4.5 版本升级、为字段和配置添加长度限制，并认为框架实例识别更适合放到 KIP-1324 讨论。

@Lianet Magrans: 提出是否应识别“框架实例”而不仅是框架类型和版本，并关注 ClientTelemetryContext 新方法缺少默认实现、用户配置与框架配置覆盖关系，以及是否允许拼接格式。

Jun Rao 已对更新后的 KIP 表示 LGTM；框架实例识别等扩展问题计划在 KIP-1324 中继续讨论，同时仍有若干 Connect、配置覆盖和验证规则细节待进一步确认。
