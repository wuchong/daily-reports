@Arnab Nandy: 推进 client/broker 实现，确认使用反射调用 API、不校验兼容性，并将更新空值语义、文档和后续 PR 范围。

KIP-1349 : Configurable snapshot frequency for share groups

0 条回复 · 1 位参与者

讨论围绕 KIP-1349 中 share group 快照频率配置应采用按字节还是按记录数阈值展开。核心进展是确认快照清理受同一 state partition 中最慢组限制，因此按字节阈值难以直接控制日志保留，讨论倾向于按组配置记录数阈值。

@Chia-Ping Tsai: 由于清理需等待所有 share partition 完成快照，按字节或按分区阈值都难以让用户准确评估保留日志大小；支持 per-group 配置，认为 per-group count 加提高 broker 上限可能足够。

@Muralidhar Basani: 快照清理点由最慢组决定，低频组会拖住磁盘空间释放；更新记录大小较固定，按计数与按字节效果接近。

@Muralidhar Basani: 此前曾按建议改为 bytes，但认为该场景下 bytes 不如 count 实用，将把 KIP 改回 count-based。

初步方向是放弃 bytes 阈值，改回基于记录数的 per-group 快照频率配置；Murali 将修订 KIP 并继续跟进讨论。

KIP-1163: Diskless Core

0 条回复 · 1 位参与者

本次讨论围绕 KIP-1163 Diskless Core 中 Diskless 主题与 ISR 机制及经典模式迁移的关系。Greg 说明纯 Diskless 主题通常保持空 ISR 且不进入错误状态，而迁移中的 Hybrid 主题仍沿用 ISR。Viktor 补充了 KIP-1165 的对象整合设计，并讨论基于对象存储恢复副本与本地日志构建策略。

@Greg Harris: 纯 Diskless 主题通常维持空 ISR 且不视为错误；Hybrid 主题在经典与 Diskless 模式迁移期间仍使用 ISR。

@Viktor Somogyi-Vass: KIP-1165 更新为对象整合（object consolidation），用于把 WAL 段转换为经典 Kafka 日志；当前仍假设 ISR，幂等与事务支持留作后续工作。

@Viktor Somogyi-Vass: 副本可从对象存储拉取数据而无需等待本地日志完全追赶，并提出从最早非分层 offset、最新 offset 或可配置数据量开始构建本地日志的策略。

初步方向是区分纯 Diskless 与 Hybrid 主题的 ISR 语义，并继续完善对象整合及副本恢复策略；下一步将更新相关 KIP 和讨论线程，推进 JR3、JR4、JR5、JR6.2 等事项。

Qestions for migrating KRaft kafka dedicated controllers to combined broker/controller role nodes

0 条回复 · 1 位参与者

讨论围绕如何将 KRaft 集群从 3 个专用 Controller 节点迁移到 broker/controller 混合角色节点展开。发件人表示社区此前认为其原地迁移方案可行，但进一步询问迁移过程中是否必须停集群、落后节点加入新 quorum 的影响，以及是否可以不重格存储。

@Xiong, Benson: 希望确认整个角色迁移是否可以避免停止整个 Kafka 集群，即在专用 Controller 和混合角色 Controller 共存的情况下完成迁移。

@Xiong, Benson: 本地测试显示，即使某个未来 voter 节点因停机导致元数据落后，加入新的混合角色 quorum 后仍可追赶，且未发现数据丢失或发布订阅异常。

@Xiong, Benson: 官方文档称角色变更需要重格存储，但本地测试表明不清空/重格存储也可能完成迁移，因此希望社区确认安全性。

目前尚无最终结论；此前社区认为原地拓扑变更可行，但仍需进一步确认不停机迁移、落后节点加入 quorum 以及免重格存储的安全性和正确操作步骤。
