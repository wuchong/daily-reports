FLIP-612: Native XML Functions for Flink SQL

7 条回复 · 4 位参与者

讨论围绕 FLIP-612 为 Flink SQL 引入原生 XML 函数展开，核心关注 XML 解析为 VARIANT 后的结构设计、访问易用性以及命名空间处理。社区整体认可该设计，并重点讨论了重复元素是否应统一表示为数组，以保持同构 XML 文档转换后的 VARIANT 结构一致。

@Fabian Hüske: 建议将 XML 元素统一映射为数组，避免同构文档因元素出现次数不同而产生不一致的 VARIANT 结构，从而减少 CASE WHEN 等复杂处理。

@Timo Walther: 支持该 FLIP，但认为默认应优先保证 a.b.c 这类简洁访问方式，数组索引可作为可选参数，未来也可通过 XML_PATH 等函数改进访问。

@Krishna Sai: 关注 xmlns 声明和 xsi 前缀在 PARSE_XML 与 XML_STRING 往返转换中的处理，指出可能导致命名空间语义变化的边界情况。

初步结论倾向于默认采用紧凑结构以保持 a.b.c 访问，同时提供可选参数使所有元素包装为数组以保证结构一致；Timo 表示支持投票，但仍需在 FLIP 中补充说明 Sai 提出的命名空间边界问题。

Emit "Z" instead of "+00:00" for UTC in Variant.toJson()

2 条回复 · 3 位参与者

讨论围绕 Flink 新 VARIANT 类型的 Variant.toJson() 输出格式展开，提议将 UTC 零偏移时间戳从 '+00:00' 改为更标准的 'Z'。参与者普遍支持该变更，认为其符合 ISO 8601/RFC 3339 和主流 Java/JSON 库习惯，且因 VARIANT 较新影响面可控。

@Ramin Gharib: 提议将 Variant.toJson() 中 UTC 时间戳偏移输出由 '+00:00' 改为 'Z'，以提升标准兼容性、可读性和紧凑性，并建议在 VARIANT 广泛使用前尽早调整。

@Timo Walther: 支持该变更，认为 UTC 时间戳应使用 'Z'，且解析器通常兼容两种格式，当前 toJson 主要用于打印输出，因此风险较低。

@Krishna Sai: 验证后支持变更，指出该改动会影响 toJson、JSON/raw sink 等输出但不影响 CAST(VARIANT AS STRING)，并提醒发布说明需注明影响范围及 Python 3.9/3.10 对 'Z' 的兼容性问题。

初步达成共识支持改为输出 'Z'；下一步由 Ramin Gharib 提交 JIRA 和 PR，更新相关测试，并在发布说明中说明受影响的输出场景和兼容性注意事项。

[Flink CDC][postgres] JobManager connection pool exhausted after 20 incremental-snapshot jobs: JdbcSourceChunkSplitter keeps a pooled JDBC connection for the whole job lifetime

1 条回复 · 2 位参与者

讨论围绕 Flink CDC PostgreSQL 增量快照作业导致 JobManager JDBC 连接池耗尽的 bug 展开。Kyrie 指出自 CDC 3.3.0 引入异步切分后，JdbcSourceChunkSplitter 会在整个作业生命周期内持有连接，导致同库作业超过默认连接池大小（20）时新作业启动失败。目前问题已定位，Kyrie 已提交修复 PR 并完成验证。

@Kyrie: JdbcSourceChunkSplitter 在 open() 时获取连接，直到作业结束 close() 才释放，导致每个增量快照作业长期占用一个 HikariCP 连接，最终耗尽连接池。

@Hongshun Wang: 确认该问题对应 JIRA FLINK-34623，并将其分配给 wglbd12 处理。

@Kyrie: 已提交 PR #4534，将连接生命周期恢复为按表获取和释放，并在 30 个 postgres-cdc 作业场景下验证连接数从 31 降至 1。

初步结论是确认该行为为 bug，修复方案已提交（PR #4534），下一步是等待 committer 审批 CI 并进行代码评审。
