@Lazarev Artemiy Maksimovich: 报告 State V2 的 getUnionListState 将 V2 描述符转换后错误调用 getListState，导致状态模式变为 SPLIT_DISTRIBUTE。

@Krishna Sai: 确认该行为符合 bug 表现，复现了恢复时状态被拆分的问题，并指出启用 async-state 的 SQL 场景也会受影响。

@Krishna Sai: 已创建 FLINK-41532 并表示将跟进修复。

初步结论是该问题为 bug；下一步行动是围绕 FLINK-41532 进行修复。

Flink support for the proposed Parquet SERIALIZED_VALUE type

0 条回复 · 1 位参与者

讨论 Flink 是否支持 Parquet 提议的新逻辑类型 SERIALIZED_VALUE，用于在 BYTE_ARRAY 列中保存序列化的 protobuf、FlatBuffers 或 thrift 消息，并附带格式、schema 和根消息类型。提议认为该类型可帮助 Flink 在文件场景中直接读取自带 schema 的序列化消息，减少对编译类或外部 schema registry 的依赖，但需要升级 parquet-java 版本。

@Neelesh Salian: SERIALIZED_VALUE 只负责在 Parquet 中保存原始序列化字节和 schema，不解码内容；Flink 可基于此实现消息字段读取、字段暴露和投影读取，并自行负责解码逻辑。

@Neelesh Salian: 当前 Flink 的 protobuf format 依赖生成的消息类且文件系统连接器支持有限，SERIALIZED_VALUE 可为文件读取场景提供类似 schema registry 的能力。

@Neelesh Salian: 读取该类型需要 parquet-java 1.18.0 或更高版本，因为 Flink 当前使用的 1.15.2 版本无法识别未知逻辑类型。

目前仍在征求 Flink 社区反馈，尚未形成最终结论；如果方向获得认可，下一步将推动 FLIP 讨论直接读取消息字段和投影列，并评估升级 Parquet 依赖。
