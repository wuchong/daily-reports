FLIP-XXX Support ReducingMergeState and AggregatingMergeState backed by Java based associative merge operators

2 条回复 · 2 位参与者

讨论围绕是否应在 Flink 中支持基于 Java 关联合并算子的 ReducingMergeState 和 AggregatingState 展开。Roman 质疑在存储层利用结合律的效果，认为数据流层的两阶段聚合更能解决扩展性问题；Soumitra 则辩称该提案旨在暴露 RocksDB 现有的高性能异步合并机制，以提供比现有 State 更优的运行时特性。

@Roman Khachatryan: 关联操作更适合在数据流层（如两阶段聚合）而非存储层利用，因为存储层合并无法解决单点热键扩展问题，且可能增加读后写场景的开销。

@Soumitra Kumar: 该提案旨在将 ListState 底层已使用的 RocksDB 异步合并能力暴露给 Java 用户，允许自定义关联算子，从而减少状态大小并优化特定场景下的读取性能。

Soumitra 将在近期提供具体的建议和性能测试数据，以证明该方案在特定场景下的优势。
