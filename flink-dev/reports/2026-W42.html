FLIP-616: Materialized Tables support for Table API

5 条回复 · 3 位参与者

@Timo Theusner: 说明 Table API 与 SQL 创建的 Materialized Table 在 original/expanded query 上的差异，不可序列化查询会在写入 Catalog 前被拒绝；选项变更按调用顺序生效，并计划补充文档。

@Xuyang: 认可使用 resume() 作为刷新作业丢失后的恢复方式，并曾建议增加类似 FORCE 或 IGNORE NOT EXISTS 的可选参数，以便在保留表数据的情况下重启作业。

@Gustavo de Morais: 支持该 FLIP，认为 Materialized Tables 是简化 Flink 作业创建的重要能力，在 Table API 中暴露该能力是合理的。

初步共识是不额外引入恢复参数，而是通过 resume()、警告日志和文档说明来处理刷新作业丢失场景；Timo 将更新 FLIP，并计划在无反对意见后发起投票。
