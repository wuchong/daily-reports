FIP-48: Introduce a Union Read Kernel for fluss-rust

0 条回复 · 1 位参与者

Jim Hu 发起关于 FIP-48 的讨论，旨在为 fluss-rust 引入 Union Read Kernel，以便非 JVM 引擎（如 StarRocks、DataFusion）无需嵌入 JVM 即可读取启用 Lake 的表。该提案计划新建 fluss-lake crate，提供有界批量读取模型、统一的扫描读取契约及谓词下推等特性，目标是将 Java 引擎已有的能力扩展至 Rust 生态。

@Jim Hu: 提案核心是构建 fluss-lake crate，实现“快照+日志尾”无缝拼接的有界批量读取模型，支持引擎直接消费 Arrow 流而无需重复实现逻辑。

@Jim Hu: 该方案支持三种读取语义（Append/Log 表、主键表、仅 Lake），并具备谓词下推、分区/桶自动裁剪及类型化错误处理能力。

@Jim Hu: 此功能是对 FIP-6（Java 端能力）的补充，旨在消除非 JVM 生态访问 Lake 表的 JVM 依赖障碍。

目前处于意见征集阶段，若无进一步异议，计划于下周启动投票流程。
