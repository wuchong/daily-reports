FIP-38: Global Secondary Index

0 条回复 · 1 位参与者

邮件围绕 FIP-38 全局二级索引设计展开，重点讨论 DDL 入口统一、索引 bucket 配置以及主表到索引表的复制方式。作者根据 Jark Wu 的反馈更新了方案，采用 Schema 作为索引定义的权威来源，并将复制模式从 pull 改为 push，同时补充了幂等性和进度恢复机制。

@Jark Wu: 建议避免 DDL 双入口，Java API 使用 Schema 定义索引，SQL connector 使用按索引命名的属性，并重新考虑 push 复制模式。

@pl: 已采纳 Schema 统一入口：Java API 通过 Schema.index(...) 声明索引，Flink SQL 使用 secondary-index..* 选项并转换为 Schema 定义。

@pl: 改用 push-based 复制：主表 bucket leader 消费已提交 WAL，并通过 PutIndex RPC 推送索引变更，同时通过 per-source-bucket PROGRESS 保证幂等和故障恢复。

初步结论是采用 Schema 作为索引定义权威来源，并使用 push 模式进行索引复制；后续仍需完善分区清理、故障恢复细节以及 Spark 集成等工作。
