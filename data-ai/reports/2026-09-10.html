ClickHouse 发布 WalShadow：从 Postgres 物理 WAL 实现亚秒级复制

📌 ClickHouse Blog

2026-09-10

ClickHouse 推出 WalShadow，可直接从 PostgreSQL 物理 WAL 复制数据到 ClickHouse，官方基准显示约 200 毫秒延迟和每秒 289,000 行写入。该方案面向将操作型 Postgres 数据实时同步到分析引擎的场景，减少传统逻辑复制和 ETL 链路带来的延迟与复杂度。

📊 数据平台影响：Postgres 到 ClickHouse 的低延迟同步可简化实时分析链路，提升 CDC 替代方案竞争力，也要求数据平台关注一致性、故障恢复和元数据映射。

ClickHouse 推出 On-Demand Compute：按需扩展高强度查询算力

📌 ClickHouse Blog

2026-09-10

ClickHouse 发布 On-Demand Compute，允许单个查询临时调用额外 worker，在不影响生产集群的情况下运行高强度工作负载。该能力面向突发报表、复杂分析和大查询场景，使 ClickHouse Cloud 能按查询需求弹性扩展算力，而不是长期预留资源。

📊 数据平台影响：按需算力进一步模糊数据仓库与弹性计算边界，有助于成本优化，但也需要更细粒度的资源隔离、查询优先级和成本归因机制。

AWS 展示用 Iceberg 物化视图加速 Spark 查询

📌 AWS Big Data Blog

2026-09-10

AWS 介绍如何在 Amazon EMR 和 AWS Glue 中利用 Apache Iceberg 物化视图自动重写慢速重复的 Spark SQL 查询。该方案无需改写 SQL，即可在 AWS Glue Data Catalog 中透明替换匹配查询计划，从而加速开放表格式上的分析负载。

📊 数据平台影响：Iceberg 物化视图与自动查询重写强化了开放湖仓性能层，推动湖仓从存储格式竞争转向查询优化和元数据治理竞争。

AWS 发布从 CloudSearch 迁移到 OpenSearch Serverless 的指南

📌 AWS Big Data Blog

2026-09-10

AWS 发布迁移指南，说明如何将 Amazon CloudSearch 域迁移到 Amazon OpenSearch Serverless，包括评估配置、创建显式索引映射、转换文档和查询到 OpenSearch Query DSL、配置安全、使用 OpenSearch Ingestion 加载数据并验证结果。

📊 数据平台影响：AWS 推动搜索工作负载向 OpenSearch Serverless 集中，利于统一搜索、向量与日志分析底座，但迁移中的查询语义兼容和权限模型需要重点评估。
