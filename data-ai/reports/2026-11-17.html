Amazon Kinesis Data Streams 推出 queues 消费模式

📌 AWS Big Data Blog

2026-11-17

Amazon Kinesis Data Streams 推出 queues，为 on-demand stream 提供新的记录消费方式。队列可逐条投递记录、跟踪投递状态、重投未确认记录、将持续失败记录转入 dead letters，并随 backlog 扩展。该能力面向需要更可靠任务级处理的实时管道，减少用户自建队列与状态管理负担。

📊 数据平台影响：流处理可从分区消费扩展到队列语义，提升可靠投递与重试能力，降低实时 ETL、事件驱动架构和 AI 数据管道的运维复杂度。

ClickHouse Cloud 与 Claude Platform 打通链接计费

📌 ClickHouse Blog

2026-11-17

ClickHouse Cloud 支持将 Claude Platform 组织链接到 ClickHouse，用于 ClickHouse Agents 和 AI Functions 中的 Claude API 使用。客户可直接在现有 Anthropic 条款下计费，无需为数据库内 AI 调用单独建立新采购流程。此举降低 ClickHouse 用户使用 LLM 的商务与运维门槛。

📊 数据平台影响：数据库与 LLM 的计费打通后，企业更容易在 SQL/Agent 工作流中调用 Claude，推动数据平台从查询引擎转向 AI 应用运行时。

Amazon MSK Express brokers 上线 Graviton4 M8g 实例

📌 AWS Big Data Blog

2026-11-17

Amazon MSK Express brokers 现已支持 AWS Graviton4-based M8g instances。相比 M7g，M8g 提供低 15% 的 broker-hour 价格、更低 P99 produce 延迟、更快消费者恢复、新增 24xlarge 规格，并免除跨 AZ 客户端流量的 broker 侧费用。该更新强化托管 Kafka 在成本和性能上的竞争力。

📊 数据平台影响：托管 Kafka 成本与延迟优化有利于高吞吐事件流、日志和 CDC 场景，降低实时数据管道的总体拥有成本。

ClickHouse 使用 TimesFM 时序基础模型进行预测与异常检测

📌 ClickHouse Blog

2026-11-17

ClickHouse 展示如何将 TimesFM 时序基础模型通过 executable UDFs 连接到 ClickHouse，在 SQL 中完成零售需求预测、异常检测，并纳入已知未来事件。该方案把基础模型推理嵌入分析数据库，减少数据搬运和外部模型服务编排。

📊 数据平台影响：时序预测与异常检测可直接发生在数据仓库/数据库内，有助于缩短 BI 到 AI 决策的链路，提升运营分析自动化水平。

Veeva 基于 Amazon EMR on EKS 重构 PB 级大数据分析平台

📌 AWS Big Data Blog

2026-11-17

Veeva Systems 基于 Amazon EMR on EKS 与 Karpenter 重建 PB 级分析平台，将 ETL 运行时间缩短 50% 以上，并通过弹性 Spark 计算消除空闲集群成本。集群可在数分钟内从 40 节点扩展到 520+ 节点，体现云原生大数据架构的弹性优势。

📊 数据平台影响：EMR on EKS 与 Karpenter 组合为大规模批处理提供更强弹性，适合需要峰值扩展和成本治理的现代数据湖仓架构。
